# 无提示检测：留空就开始

## 操作

1. 关闭旧版窗口，再在项目中运行 `python main.py` 或 `run_app.bat`。沿用本机 `6008` 环境。
2. 在“1. 无提示 / 开放文本检测”页选择图片、图片文件夹、视频或摄像头。初次尝试建议 26S、640，关闭切片 / 暗光补检。
3. 提示词不填写，直接点“开始检测”。不再弹“请输入提示词”；如果尚未加载所需权重，会按当前 CPU / CUDA 选择加载，左侧显示实际文件。
4. 需要指定目标时输入 `person, bottle, cup` 等文字，再开始。若刚才正在无提示检测，修改为文字会先停止，点击开始后切回原版。
5. 参考图检测使用第 2 页：上传参考图片、框选目标，再开始。PF 权重无法接收参考图，程序会使用对应的原版而不修改 PF 权重。

“应用设置 / 加载模型”仍可手动预加载所选文件。自动模式切换不弹成功框；资源异常、错误和训练确认不被隐藏。语言切换不换模型、不翻译词汇表类别或用户提示。

## 两类权重不能混用

| 同规格模型 | 文字 / 参考图权重 | 真正无提示权重 |
| --- | --- | --- |
| 26S | `yoloe-26s-seg.pt` | `yoloe-26s-seg-pf.pt` |
| 26L | `yoloe-26l-seg.pt` | `yoloe-26l-seg-pf.pt` |
| 26X | `yoloe-26x-seg.pt` | `yoloe-26x-seg-pf.pt` |
| 11L | `yoloe-11l-seg.pt` | `yoloe-11l-seg-pf.pt` |

PF 是官方 LRPC 检测头和 4,585 个内置名称，加载时检查该头和完整词汇数。检测不调用 `set_classes()` 或文字编码器，不用空输入触发原文字引擎的 7 类占位列表，也不设置 COCO 80 类。原版则允许用户指定新文字类别或视觉示例，不局限于 80 种物体。见 [官方模式说明](https://docs.ultralytics.com/models/yoloe/#choosing-a-prompting-mode)。

类别多不等于“所有东西都能正确识别”。内置名称可能有近义词、泛称或不符合预期的标签，同一位置也可能预测不同概念。阈值 0.40 是默认筛选门槛，框数上限 300、NMS 与跟踪也会筛选结果；可以调整参数观察，但不能把框数增加当成准确率提高。更多重叠框和标签也可能造成画面拥挤。

## 下载与保护

```powershell
# 默认：原版 26S、文字编码器 MobileCLIP2、26S 无提示权重，约 310 MiB。
python tools/fetch_models.py
# 四种 PF 权重，合计 401,962,344 字节，约 383 MiB。
python tools/fetch_models.py --prompt-free
# 全部十份原版 / 编码器 / PF 权重。
python tools/fetch_models.py --all
```

PF 来自 [Ultralytics 官方 v8.4.0 发布](https://github.com/ultralytics/assets/releases/tag/v8.4.0)，具体 URL、大小和官方 SHA-256 固定在 `model_sources.json`。下载完成且校验通过后才替换下载目标；已有且校验通过的文件不重复下载。原仓库权重的固定来源保持不变。运行时不自动下载、拼接词表、转换或重参数化原权重。

继续使用已有依赖，Ultralytics 8.4.172 已支持这些 PF 文件。权重只留在本地，受 `*.pt` 忽略规则保护。原推理 GPU 锁、3 GiB 预算、空闲显存 / RAM 检查、batch=1、最多 9 个串行切片及 OOM 停止行为不变；不偷偷换到 CPU。

## 纠错型与 DINO

纠错训练生成的 A（纠错型）仍保留文字和参考图功能，但不能凭文件名得到同样经过纠错的 PF 权重。DINO 也需要文本输入。因此这两类模型留空时只在页面和状态栏解释，不加载官方 PF 来冒充原模型；可明确在下拉列表选择 PF，或填入文字继续使用当前模型。

PF 的检测候选框可进入人工纠错页，保存时仍用原始类别名而不是 person1 等跟踪编号。训练请选择可提示的原版或纠错型作为父模型；后台也拒绝融合 / LRPC 头，防止产出不满足双提示要求的“纠错型”。这次没有新增纠错型的 PF 转换训练。

## 本轮实测范围

- 276 项单元 / 回归检查：275 通过、1 项缺少完整 COCO 原始标注缓存而跳过。
- CPU：26S-PF 使用 `datasets/mini_eval/images` 全部 24 张真实图片；26L-PF、26X-PF、11L-PF 各使用双人照片 `000000066771.jpg`。四个文件均确认完整 4,585 类和 LRPC 头，预测 ID 可以超过 79，未注入提示词。
- CUDA：四种 PF 各使用同一张双人照片，通过项目 GPU 锁与预算。在本机该次运行中峰值 PyTorch 分配约 318 / 509 / 920 / 458 MiB，不是其它图片、分辨率、硬件或训练的内存保证，也不作为跨主机性能比较。
- 真实 Qt：空输入、图片翻页、中文 / 英文切换，以及 PF → 原版文字 → 原版视觉参考 → PF。视觉参考来自独立 COCO 人工框，完成真实编码 / 推理；结果不表示精度改善。切换文字 / 视觉仍复用原版，切换 PF 则释放并换文件。
- PF + SAHI 使用真实双人图，最多 9 个串行切片限制保留；录像使用同图重复生成的 4 帧视频，验证视频处理及 MP4 输出，不代表真实运动跟踪或摄像头测评。
- 正常检测路径没有弹窗，原图片及四种原版权重前后 SHA-256 一致。私有 QA 输出、参数、设备和代码 / 模型 / 数据哈希保存在 `.local-deployment/prompt-free-20261013/`，不上传。

没有测试真实摄像头、长时稳定性、无提示 AP / 召回率或纠错型 PF 训练。`mini_eval` 是开发诊断资料，不是未见最终测试集；只看预测框不能当作完整人工真值。
