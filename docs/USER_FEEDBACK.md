# 用户纠错与迭代优化（2026-10-13 一键更新、单一修改版）

界面左上角 `语言 / Language` 在所有分页可见，可切换中文 / English。纠错说明、审核选项、样本状态、训练进度和项目提示同步切换；未保存标注、整图审核确认、场景名、类别、数据版本和训练进程不会重置。数据记录保留原内容，第三方原始诊断信息保留原文。

## 默认：改框后点一次按钮

1. 检测后点击“纠错当前结果”，或直接打开图片手动补框。
2. 选中框，在右侧修改类别；也可补框、拖动框或删除误检。无需单独点“修改所选框类别”，更新按钮会应用仍留在输入框中的类别。
3. 点击 **一键更新并重测当前图片**。自动保存、合并类别、准备累计演示数据、真实训练、更新唯一修改版权重、选择修改版并重测本图。不必勾审核、不必选训练 / 验证、不必手动导出，没有普通确认或完成弹窗。
4. 等待页内进度完成。默认 20 轮，轮数可调整；CPU 可能较慢。成功后回到第 1 页显示新权重的预测，左侧已选择如 `YOLOE-26S修改版`。在其它图片、视频、摄像头、文字或视觉提示中也可选择这同一个模型。

点击按钮表示采用当前整张图的全部框用于演示，未删除的候选也会被采用。只改一个框而其它候选错误时，新模型也可能学习这些错误；不是在后台自动生成“严格人工真值”。允许单图训练后直接复测同图，不再要求准备独立验证照片；这个结果只是拟合演示，不作为未见照片准确率或泛化证明，也不保证一次更新完全学会。

普通成功、错误和进度留在页内及状态栏。切换 / 关闭未更新图片时自动暂存演示草稿，不弹放弃确认，也不擅自训练；高级样本列表可重新打开草稿。训练失败或取消保留原版和上次完成的修改版。完成后自动重测仍是模型推理，人工框只参与训练，不参与预测框绘制。

演示记录另存 `feedback_data/demo/`；原来严格记录的用途和内容不改写。累计训练包括同型号最新已采用演示修订，以及原有已人工审核训练图；草稿和原有验证 / 保留测试图不自动参与。用户明确对测试 / 开发诊断图点击一键更新时，允许另存一份演示训练记录，但不能再拿它证明未见泛化。后续权重记录保留 `demo_exposure` 标记，不通过重新命名或再次严格训练假装从未见过这些图。

## 高级：严格审核与独立验证

默认收起“高级样本管理”。需要规范数据用途、独立验证或手动导出时再展开，以下操作属于高级流程；日常演示不必逐项执行。

### 模型不会因仅保存一个框立即改变

原始 A 的权重文件不修改。你先积累并审核纠错样本，再明确生成或更新 A 修改版，例如 `YOLOE-26S修改版`。每个基础型号最多一个固定修改条目；后续从它继续训练并重新使用同型号全部已审核纠错，不生成带时间后缀的多个修改模型。仍使用开放文字提示和完整参考图片框选，不限制以后只输入训练过的类别。

“仍支持提示功能”不等于“所有未知类别都和原版一样准”。修改版更新了检测分支，可能改善某些目标，也可能损害其它目标；保留原版并比较实测结果，不宣称微调必然提升。

### 1. 打开原图并改框

1. 在全局设置选择 YOLOE，应用设置，检测一张图片或启动视频/摄像头。
2. 点击文字页或视觉页的“纠错当前结果”，进入第 3 页。视频采用最后已完成检测的单帧，不连续保存视频，也不复制整段录像。
3. 可直接打开图片手动标注，不依赖模型先检出目标。
4. 选框后填写类别，点击“修改所选框类别”；删除误检框。切换“拖拽补框”补漏检；需要调整框尺寸时删除旧框重画。选择模式可以拖动框。坐标换算回原始图片，黑边不参与标注。

保存的是未增强、未叠加标记的原始 BGR 画面，PNG 无损保存。person1/person2 是跟踪编号，候选类别保留 person；不是按人身份训练。候选框和人工修改后的框分开记录。

### 2. 确认整图、分组、保存

填写当前图片需要审核的全部类别，推荐简短明确的英文名称，用逗号分隔。每张图都要检查这些类别的所有实例；不能只修一个框而漏掉其它目标。累计导出会合并同一基础型号各图的审核类别，但训练每张图仅监督该图的已审核类别，不把新类别自动当作旧图背景。

纠错归属在采样时记录；原版、无提示版和对应修改版都归属同一基础规格，例如 26S。26L 的纠错不会混入 26S 数据。左侧切换型号只切换样本列表和导出目标，不清除未保存画布；保存后请在对应型号下导出。

- 未勾选人工确认：保存为草稿，不导出训练。
- 勾选“我已检查整张图”：包括补齐漏检、删除误检、改正确类别。没有这些目标的图片也可以确认并保存，作为负样本。
- 修改类别、框或审核范围后，需要重新确认；保存产生新修订，旧修订不覆盖。样本列表双击可继续审核。

场景组可填写“宿舍桌面_白天_拍摄1”等。选择训练、验证或保留测试用途。同一原图、同一来源视频/图片目录或场景不允许跨用途；因此训练和验证应从不同视频/拍摄场景及目录准备，不是把连续帧随机拆开。摄像头默认按会话分组，同一实际场景的多次会话应填写相同场景名。

旧 `mini_eval` 开发诊断图、`mini_development_quick` 和视觉参考不能作为训练/验证输入。第一版不提供跨拍摄会话的视觉近重复识别，用户仍须检查实际场景是否独立；移动/重命名视频也应保留原场景组。

### 3. 导出数据，再手动训练

至少准备一组人工审核的训练图和一组独立验证图，点击“导出当前型号全部已审核纠错”。草稿自动排除。导出版本包含原图、YOLO 框标签、类别并集、每图审核范围、原始纠错记录、基础型号、分组、代码/文件 SHA-256。更正旧图会产生新修订，下次导出采用最新已审核记录；未审核新类别不会被自动当作旧图背景。不能修改旧清单或指纹来绕过检查。

选好基础 YOLOE 或其修改版以及 CPU/CUDA，点击“生成 / 更新唯一修改版”。首次使用原版，后续自动使用同型号当前修改权重作为父模型。确认后停止本项目检测并释放模型，启动使用同一 Python 环境的独立进程。PF 只能提供候选框，训练用同型号可提示的权重，不能直接训练融合的 PF 头。不同电脑的纠错没有自动同步。

采用保留整个 YOLOE 分割模型结构的框检测损失，仅训练检测框、区域特征和对比检测分支（及对应 one2one 分支）；骨干、文字对齐 RepRTA、视觉提示 SAVPE 与 mask 分支参数和统计量冻结。当前也冻结检测头的 BatchNorm 运行统计，batch=1 时只更新可训练参数，避免单图统计漂移造成误检暴增；训练、保存及重新加载检查其指纹。没有把矩形框伪造为人工分割掩码。类别词通过原有文本编码器参与训练，不做固定类别的提示融合。优化器为 AdamW，学习率 0.0001，batch=1，输入 640。高级严格流程默认 3 轮，按独立验证框损失选候选；一键演示默认 20 轮，每轮更新后按同图推理模式的拟合损失选候选，不伪装独立验证。首版没有自动扩展样本、蒸馏、后台自动重训或无限超参搜索。

这不是闭集 PE 微调，也不是官方大规模开放词汇训练配方的复现；它是本项目的保守检测头纠错实现。数据范围窄时仍会过拟合。验证损失只能用于本次同一数据版本的候选选择，不能当作检测 AP、真实准确率或跨版本性能证明。

CPU 训练可能很慢。CUDA 开始时需至少 8 GiB 空闲显存、4 GiB 可用系统内存、3 GiB 输出磁盘空间；PyTorch 训练预算独立设为 6 GiB，运行时仍检查至少 1 GiB 空闲显存和 1.5 GiB 系统内存。GPU 文件锁与现有推理共享；其它进程占锁则停止，不结束其它进程、不自动切换 CPU、不重试 OOM。全部样本单张、串行处理。

点击“请求停止训练”在下一张图片前停止；训练进行中不能关闭窗口或加载推理模型。一次 native 前向/反向尚未结束时，停止不会瞬间完成。强制退出或失败的目录不会注册为可用版本。

### 4. 选择新模型或回退

首次成功后模型列表出现 `YOLOE-26S修改版` 等固定条目；后续更新同一条目及同一路径。应用设置或重新开始检测时检查当前指纹，内容更新后重新加载；仍可在文字页换类别、视觉页换参考图，并使用图片、视频、摄像头、跟踪、小目标切片与暗光处理。推理结果由当前模型产生，历史人工框不参与绘制预测。该检查不保证每种类别都能检出目标。

原模型仍在列表，随时选择它即可比较或回退。更新过程中不加载第二个推理模型，通过检查才提交新权重，失败保留上次可用修改版。界面不保留多个修改代次；完成后删除本轮临时权重，保留审计日志。旧版已经生成的历史文件只读兼容，不自动删除，列表每个型号也最多一个。

修改版目前没有独立的无提示转换文件，留空时不会偷偷回到未经修改的官方 PF；请填写文字或使用参考图。模型词汇能力保留不等于未知类别精度不下降。用训练图复测只能说明对该图的学习效果，不能当作未见图准确率。

## 本地文件

```text
feedback_data/                         # 全目录忽略，不上传 GitHub
├─ demo/
│  ├─ images/<像素哈希>.png            # 一键演示原图，不改旧严格图片
│  └─ records/<修订>.json              # 明确采用 / 演示草稿，不冒充严格审核 GT
├─ images/<像素哈希>.png               # 去重后的未画框原图
├─ records/<时间+随机编号>.json        # 追加式纠错、候选和人工确认记录
├─ datasets/<版本>/
│  ├─ images/{train,val,test}/
│  ├─ labels/{train,val,test}/
│  ├─ data.yaml
│  ├─ manifest.json
│  └─ manifest.sha256
└─ models/
   ├─ yoloe-26s/                        # 其它型号分别对应自己的同名目录
   │  ├─ modified.pt                    # 唯一完成修改权重，后续更新同一路径
   │  ├─ current.json                   # 当前指纹、累计数据、更新次数与能力检查
   │  └─ publish.pending.json           # 仅提交 / 中断恢复期间存在
   ├─ .locks/                          # 按型号阻止并发更新
   └─ .staging/<训练任务>/
      ├─ parent-copy.pt / corrected.pt # 仅训练中；完成后清理
      ├─ version.json                  # 保留审计结果，不是左侧模型版本
      ├─ retest.json                   # 一键自动重测指纹、参数及真实预测（不是人工框）
      └─ cancel.request                # 用户请求停止时产生
```

程序文件：`feedback.py` 管理数据与累计导出；`model_families.py` 识别基础型号；`modified_models.py` 管理唯一修改槽、提交和恢复；`feedback_ui.py` 提供编辑界面；`feedback_training.py` 执行显式独立训练。现有视频线程只保留一个待纠错原图引用，用户打开编辑页才复制，不逐帧写磁盘。
