# 视频实时性优化（2026-10-06）

本次优化摄像头调度与可观测性，不改变检测模型、阈值、单模型策略、batch=1 或显存安全限制。

## 已实现

- 摄像头由独立 CPU 线程持续读取。待检测缓冲仅保留一张，慢推理期间新帧替换旧帧；模型推理仍全部串行。
- 摄像头的待显示缓冲也只保留一张，只在缓冲由空变为非空时通知界面，避免 Qt 队列堆积大量带图像的旧结果。
- 原有每帧固定 5ms 等待已移除。离线视频仍按源文件顺序检测每帧、保存每帧，没有采用摄像头丢旧帧策略。
- 状态栏显示实际界面更新 FPS、读帧到界面提交延迟及最近 120 次更新的 p50/p95、待检时间、检测处理时间和采集/显示旧帧替换计数。
- 摄像头录像按源 FPS（无有效值时 20 FPS）保存，用最近的处理后画面补齐间隔，避免推理变慢导致录像加速。重复帧数可见；同一时隙内的多次结果只保留适当帧。超过 10 秒未更新时停止，限制补写工作量。
- 摄像头线程独占 read/release；停止会唤醒缓冲等待，且等待读取线程退出后再结束推理线程。驱动读帧若卡死，界面停止超时后提示等待，不跨线程强制释放正在读取的设备，也不提前卸载活动模型。

## 手动实测

1. 重新启动 `run_app.bat`，选择 YOLOE-26S、CUDA、640、摄像头。先关闭 SAHI、旧分块和暗光补检，加载模型并开始检测。
2. 预热后移动瓶子、杯子或手机，观察画面是否跟随当前动作。最初的预热延迟会暂时进入滚动统计，持续运行后再记录稳定值。
3. 查看底部状态栏。`显示 FPS` 是界面实际接收并提交处理结果的更新速率；第一张尚无帧间隔，显示为 0。
4. `读帧→界面` 是 OpenCV read 返回后到 Qt setPixmap 完成的时间，包含待检、检测、画框、录像、颜色转换及 GUI 等待。它不包含曝光、设备/驱动内部缓存或屏幕实际刷新，因此不能称为完整传感器到屏幕时延。
5. `旧帧替换：采集` 表示已读取但未进行检测的旧帧数量；`显示` 表示检测完成但尚未显示就被新结果替换的数量。它们是当前会话累计值，不是设备丢帧或检测漏检数量。
6. 可保持其余参数不变，只打开 SAHI，观察处理时间上升时画面是否仍优先更新当前帧。旧帧替换计数上升可能是预期行为，不等于模型推理加速。
7. 开启摄像头录像并选择新的 MP4 路径，运行一段时间后停止；检查播放时长和重复帧提示。重复帧只保持时长，未采样的动作不会被恢复，也不能用文件 FPS 代表检测 FPS。
8. 用本地视频验证离线模式，检查保存文件与原视频帧数、源 FPS 一致。图片和视觉提示仍可按原方式使用。

## 验证与未验证事项

新增 CPU/mock 测试覆盖慢推理时取最新帧、有界 GUI 通知、滚动延迟、旧 worker 通知隔离、读取失败与线程安全停止，以及录像时间轴。
已有离线录像、视觉提示和模型生命周期测试也继续运行。测试日志保存到本地 `.local-deployment/video-realtime-tests.log` 和 `video-realtime-regression.log`，不覆盖历史实验结果。

实时调度提交当时全项目回归共 197 项，196 项通过，1 项因缺少完整 COCO 原始标注缓存而跳过。新增 14 项实时调度与界面测试全部通过。后续本地完整整合增加两项兼容测试，共 199 项；发布前公开版回归结果见 [公开整合更新](UPDATE_20261007.md)。

上述实时调度提交验证未采集真实摄像头画面、未加载 GPU 模型；后续本地整合做了 CUDA 和短视频功能验证，但仍未得到真实摄像头的前后延迟对比。因此不能宣称本机摄像头 FPS 或 AP 已提高。

录像编码仍在推理线程完成，慢磁盘/编码仍可能拖慢检测。快速运动时跳过检测帧可能影响 ByteTrack 关联，后续需用带实例身份的实际视频检验。采集驱动是否支持缓冲大小设置也需实机确认。

后续基准应固定模型、参数、摄像头模式及输入场景，单模型串行测试；保存设备和代码/模型/数据指纹，报告预热规则、显示 FPS、p50/p95 和替换计数，不复用旧代码指纹的实验检查点。
