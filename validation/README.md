# 本次改进验证

验证环境：RTX 5070 Laptop GPU（约 8 GB）、CUDA PyTorch 2.9.1+cu128、Ultralytics 8.4.126。

## 已通过

- 12 项回归测试：曝光与颜色、噪声、原图保留、重复框、分块坐标、模型重载、实时设置和异常释放。
- YOLOE-26L 与 26X 权重和 MobileCLIP2 文本编码器加载、文本提示推理。
- Qt 视频端到端测试：本地视频读取、后台推理、预览更新、结束与线程回收。
- 短时真实摄像头测试：实际协商到 1280×720；默认 26L / 960 在预热后单帧处理约 44–48 ms（不含摄像头采集与 UI 渲染）。未保存摄像头画面。

## 本地对比结果

完整结果见 [comparison.json](comparison.json)，命令输出见 validation_run.log。使用 Ultralytics 自带的公交车图片，对小目标与暗光做确定性模拟，所有配置使用相同的 0.40 检测阈值。

将样图缩为 81×108，放入 1920×1080 画布时：

| 配置 | 输出框数 | 单帧处理耗时中位数 |
| --- | ---: | ---: |
| 旧 11L / 640 | 0 | 34.48 ms |
| 26L / 640 | 1 | 31.84 ms |
| 新默认 26L / 960 | 4 | 40.57 ms |
| 26L / 1280 | 4 | 54.91 ms |
| 26X / 960 | 1 | 57.28 ms |

这个例子也说明：更大模型不一定在每个小目标场景更好。默认选择 26L / 960。分块模式在这次样图中没有增加检测框，且明显增加耗时，因此作为可选项，默认关闭。

暗光使用 16% 和 4% 亮度、固定随机噪声两个条件，比较原图、旧 CLAHE、仅新增强图、新补检流程。新默认配置在这两个暗光样例中都保留了原图的 5 个框；此次没有增加框，不能据此声称召回率提升。旧 CLAHE 在部分配置中降低分数，26L / 1280 的极暗样例还额外输出一个人框，需要人工审查。新流程的优势是原图已有结果和分数不会被增强结果覆盖。

独立算法耗时优化：同一张 810×1080 暗图，新算法初版约 87–99 ms，优化后约 22–27 ms。最终双路暗光检测仍包含两次模型推理，例如 26L / 960 的极暗模拟样例为约 121 ms；可选“仅增强预览”节省一次推理。

## 解释范围

以上为未标注样例的功能与性能验证，框数、分数并不是准确率、召回率或 mAP。模拟缩小和加暗无法完整复现真实摄像头的失焦、运动模糊、曝光噪声等情况。没有进行针对用户物体的数据训练，也没有完成真实暗光摄像头标注评测。

新模型的选型依据：[Ultralytics 官方 YOLOE 模型说明](https://docs.ultralytics.com/models/yoloe/)。
