# AI 多模态检测系统

基于 PySide6、Ultralytics YOLOE、Grounding DINO Tiny、ByteTrack 和 PyTorch 的桌面检测应用。支持摄像头、本地视频、单张图片和图片文件夹，重点是开放词汇检测、小目标、目标编号和暗光处理。

本次功能更新、操作方法与验证范围见 [2026-10-13 更新汇总](PROJECT_UPDATE_SUMMARY_20261013.md)。说明中的本机个人测试照片不随源码上传。

## 2026-10-28 第 4 页：文件夹自动标注

- 第 4 页从“开发中”占位改为可用的 **自动标注**（章程中的 Assisted annotation）：选择图片文件夹（JPG / JPEG / PNG / BMP，可含子文件夹、中文路径），用左侧当前模型和参数逐张串行检测，支持文字提示、留空无提示（同规格 PF 权重）和第 2 页视觉参考框；有进度条和停止。
- 人工审核沿用第 3 页画布：拖动 / 补框 / 删框 / 改类别，逐张接受、拒绝或恢复模型候选；也可按分数阈值批量接受未改动的待审图（没有候选达到阈值的图保持待审）。再次开始不会覆盖已审核或已改动的图片。
- 只导出已接受 / 已修改的图片：YOLO（`labels/*.txt` 为裁剪后归一化的 `cls cx cy w h`、`classes.txt`、`images.txt`、`data.yaml`）或 COCO（`annotations.json`，类别 ID 从 1）。每次导出带 `auto_annotation_manifest.json`，写明标签是 **模型候选经人工审核，不是独立人工真值**，并记录模型文件与 SHA-256、提示词、阈值、设备、时间和每张图的审核方式。不能用这些标签评价产生它们的模型。
- 资源规则不变：单模型、batch=1、原有加载与逐张推理资源检查；资源不足 / OOM 停止整批，不重试、不换设备；超过 1600 万像素的单张图跳过并标为失败。自动标注运行时第 1 / 2 页检测和“应用设置”会提示先停止；“停止并释放模型 / 显存”同时停止自动标注。所有新界面文字支持中英文切换。

**已验证**：新增 25 项测试；完整回归 **333 项，332 通过、1 项因缺少完整 COCO 原始标注缓存跳过**（改动前 308 项，307 通过、1 跳过）。本机 CPU 用 YOLOE-26S 对 `mini_eval` 前 5 张图真实运行文字提示、无提示（26S-PF）和视觉提示三种模式；用脚本模拟审核后导出的 COCO 可被 pycocotools 载入，YOLO 标签逐行解析通过并可被 Ultralytics 数据集读取器读取。**未验证**：本页的 CUDA / DINO、大文件夹、真实人工标注效率、候选框精度和用导出数据训练；审核进度暂不保存到磁盘（开发中）。详见 [自动标注说明](docs/AUTO_ANNOTATION.md)。

## 2026-10-13 每个基础型号只有一个“修改版”

这是固定模型管理方式的记录；默认操作现已简化为上文的一键演示流程，手动审核 / 导出仍在高级选项中。

- 同一个本地项目中，纠错按 26S / 26L / 26X / 11L 分组，各自最多一个固定条目：`YOLOE-26S修改版`、`YOLOE-26L修改版` 等。只用过 26S，就不会因为多次训练出现多个 26S 修改版本。原版权重不覆盖；首次通过训练检查后才出现修改版，不创建空壳模型。
- 保存和审核是积累数据，并不立即改变权重。第 3 页使用“导出当前型号全部已审核纠错”，再明确点击“生成 / 更新唯一修改版”。首次从原版训练，后续从当前修改版继续，并重放该型号全部已审核的最新纠错，避免只使用最后一张图。草稿不参与，保留测试图不参与训练或选模型。
- 每张图的审核类别是该图的监督范围；累计类别取该型号各图审核范围的并集。训练逐张使用各自已审核类别，不把其它图片中尚未审核的新类别当作“没有目标”的负样本。原图、来源和场景的训练 / 验证隔离与旧诊断图保护不取消。
- 修改版文件固定为 `feedback_data/models/<基础型号>/modified.pt`。训练候选先在 `.staging` 中通过权重更新、冻结模块、文字与框选参考图检查，成功后校验并提交到同一路径。失败保留上一次可用修改权重；提交有文件锁、中断记录与恢复处理。完成后清理本轮临时权重，仅保留日志与不可变数据记录，不长期积累多个完成模型。
- 左侧选择同名修改版后重新检测；程序检查权重指纹，文件名相同但内容更新时仍会重新加载，不能继续拿旧的内存模型冒充新结果。推理读取修改权重和输入图像，不用历史纠错框替换预测。
- 已有旧版训练记录兼容读取，每个型号仅显示最新可用条目；不自动删除或改写旧模型文件。不同队友电脑的数据暂不自动同步，需要另行导入 / 共享方案。DINO 不是四种 YOLOE 之一，目前不生成 DINO 修改版。

本轮用隔离的合成图进行了两次真实 CPU / 128 / 1 epoch 更新：第二次从第一次修改权重继续，加入新纠错并保留此前训练记录，始终同一路径、同一名称、仅一份完成权重；修改前后权重 SHA-256 不同，原版不变。两次均通过文字 / 视觉提示检查，并重新加载权重在 `mini_eval` 的真实双人照片上完成文字 → 框选参考图 → 文字推理，确认读到对应新指纹。测试修改权重没有加入正式用户数据目录。该结果只验证累计更新、模型重载和两种提示功能，不证明真实纠错精度提升、单次立刻学会或 CUDA 训练效果。完整回归 **291 项，290 通过、1 项缺少完整 COCO 原始标注缓存而跳过**。操作见 [用户纠错说明](docs/USER_FEEDBACK.md)。

目前保留左侧四种普通 YOLOE 和四种 PF 选项；它们是同一基础规格的不同模式权重，不是八种基础架构，额外 DINO 是独立对照。本轮按用户选择，修改版先支持文字与参考图，不接入修改版的 PF 转换，不能用未修改的官方 PF 冒充修改效果。

## 2026-10-13 真正无提示检测

- 第 1 页默认不填写提示词。点击“开始检测”时，26S / 26L / 26X / 11L 自动选择同规格的官方 `*-seg-pf.pt` 无提示权重；可以直接从模型列表选择无提示版。无提示头使用内置 **4,585 类**词汇，不调用 `set_classes()`，也不是用 COCO 80 类或原来的 7 类占位提示代替。
- 输入文字后重新开始，自动切回同规格的 `*-seg.pt` 原版；框选参考图的视觉页也使用原版。文字与视觉提示仍可复用同一份原版权重；无提示与提示权重是两份不同文件，切换先停止当前工作线程、释放旧模型，再加载一份新权重，不并行占用显存，也不改原文件。
- 左侧固定显示当前模式、实际权重文件和无提示词汇数；图片翻页、ByteTrack 编号、暗光、SAHI、视频 / 摄像头与录像共用原检测流程。运行中将提示词从空改为非空或反过来，会先停止检测，点击“开始检测”再切换，避免把文字送入不支持提示的检测头。
- 去掉空提示词警告、“设置已应用”和普通视频结束通知弹窗，改用界面说明 / 状态栏。资源不足、加载失败、保存冲突和人工训练确认等重要提醒仍保留，不屏蔽错误。
- **纠错型和 DINO 不会偷偷替换成官方未纠错模型**。它们没有对应无提示权重，留空时在第 1 页说明如何选择 YOLOE 无提示版；输入文字仍使用它们原来的权重。无提示候选框可以进入人工纠错页，但独立纠错训练应选择保留文字 / 视觉提示的原版或已有纠错型，不训练官方 PF 权重来冒充兼容模型。
- 四种 PF 权重已在本地下载、按官方发布记录校验大小和 SHA-256，新增约 **383 MiB**，原权重未改动。继续使用已有 `6008` 环境，无须新增环境依赖。权重、录像和测试日志仍不上传 GitHub。

验证：完整回归 **276 项，275 通过、1 项缺少完整 COCO 原始标注缓存而跳过**。26S-PF 在 `datasets/mini_eval` 全部 24 张真实图片上以 CPU 运行，其余三种 PF 各使用同一张双人图片；四种 PF 都在本机 CUDA 上通过该图推理。另验证真实 Qt 图片翻页、中文 / 英文切换、PF → 文字 → 参考图 → PF、PF + SAHI，以及由本地图片重复生成的 4 帧功能测试视频及 MP4 输出。正常流程没有弹窗；原图片和四份原版权重的前后哈希一致。参考图路径完成真实视觉编码和推理，不由此宣称检测精度提升。没有测试真实摄像头、长时视频或无提示精度榜单；检测框数不是准确率。

无提示词汇仍有限，包含同义词或较泛的名称；预测可能错分、漏检或出现更多误检。输出的是经置信度、NMS、最大框数和可选跟踪筛选后的结果，不是无条件显示所有候选框，更不是保证识别任何物体。操作、模型来源和限制见 [无提示检测说明](docs/PROMPT_FREE.md)，原理见 [Ultralytics 官方说明](https://docs.ultralytics.com/models/yoloe/)。

## 启动与检测

~~~powershell
python main.py
# 或在已有环境下：
.\run_app.bat
~~~

程序启动时不自动加载模型。推荐先用 YOLOE-26S、CUDA、640，关闭 SAHI、旧分块和暗光补检，选择输入，再开始检测；开始时会按提示内容加载所需权重。留空使用同规格无提示版，输入 person, bottle, cup, cell phone 等文字则使用原版。“应用设置 / 加载模型”可用于手动预加载列表中所选权重；开始时若模式不同，仍会释放并切换到对应权重。

run_app.bat 可选择 OBJECT_DETECTION_PYTHON、项目 .venv 或当前激活的环境；6008 是本机回退配置，不是组员必须使用的环境名称。停止后使用“停止并释放模型 / 显存”。

| 模型 | 主要用途 |
| --- | --- |
| YOLOE-26S | 默认实时方案起点，较轻 |
| YOLOE-26L / 26X | 更大候选，速度与精度需按场景实测 |
| YOLOE-11L | 旧模型对照 |
| YOLOE-26S / 26L / 26X / 11L 无提示版 | 内置 4,585 类，留空检测；文字 / 参考图输入会切回对应原版 |
| Grounding DINO Tiny | 英文开放词汇文本检测对照，不支持 SAVPE 页面 |

推理尺寸最高 960、原图最多 1600 万像素。提高分辨率不能恢复摄像头未拍清的细节；SAHI 增加推理次数，可能引入误检，不默认开启。

## 视觉提示与小目标

在视觉页上传完整参考图，框选目标并填写显示名称，再开始检测。名称用于显示，SAVPE 参考编码驱动检测；单张参考的外观覆盖有限，不能保证其效果优于文本。

SAHI 切片 20% 重叠、最多 9 块串行，超过限制会停止并提示调整输入或切片大小。与旧四分块补检互斥，最终结果映射回原图并去重。

## ByteTrack 编号

视频 / 摄像头同一次会话内，同类目标显示为 person1、person2、bottle1 等。低分框只能短暂续接已有轨迹，不创建新编号；停止重启、切换输入或修改提示词会开启新会话。单张图片和文件夹每张图片独立编号。

编号是运动轨迹，不是人脸或真实身份识别。长时间离开、严重遮挡、快速运动和交叉仍可能换号，不能保证永不交换 ID。

## 暗光、录像与实时指标

暗光处理使用亮度自适应提亮、温和降噪、增益限制和跨帧平滑；正常曝光自动跳过，全黑画面不制造细节。

- 原图检测 + 暗光补检：保留原图框，仅在需要时额外检测增强图；增加推理开销，新增框仍可能误报。
- 仅增强预览：增强显示，检测仍用原图，不增加模型检测次数。

摄像头采集与显示各只有一个待处理结果，较慢时新结果替换旧结果；这减少排队，不代表模型前向计算变快。离线视频按顺序处理每帧。显示 FPS 是 Qt 结果提交频率，读帧到界面延迟不包含曝光、驱动内部缓存或屏幕实际刷新。

MP4 无音轨。摄像头录像用重复处理帧保持源时间轴，重复帧无法恢复未采样动作；本地视频按源 FPS 保存处理帧。详细限制和实测方法见 [视频实时性说明](docs/VIDEO_REALTIME.md)。
